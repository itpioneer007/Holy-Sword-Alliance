# 挑战记录完整性核对 + 补录报告

日期: 2026-09-11
起因: 用户质疑「这么多页，最后就只多出了 90 多个人，你确定挑战记录里都记录了我打不过的吗」
结论: **记录没有漏人**；114 个"曾经赢过我"的对手，记录里全部都有。名单 446 → **451**。

## 一、核对方法（用游戏自带的第二个面板做交叉验证）

在挑战记录同一界面发现了 **「挑战统计」** 面板（tab 按钮 622,843）。它是**按对手聚合**的表格：

| 对手名字 | 发起挑战 | 被挑战 | 胜场数 | 败场数 |
|---|---|---|---|---|
| 恻隐的血大帝 | 4 | 1 | 0 | 5 |
| 暗影的高天使 | 1 | 3 | 0 | 4 |
| 冷却的血利刃 | 1 | 3 | 1 | 3 |
| … | | | | |

**按「败场数」降序排列** ⇒ 前 N 行 = 曾经赢过我的全部对手，一行一个人，天然去重、无需判方向。
这比 360 条流水更直接，是「打不过名单」的最佳证据源。

采集方式: `scripts/arena_stat_collect.py --rewind`（25 页 / 248 个对手 / 250 行，末页 8 行）。
> 踩坑: 点「挑战统计」tab **不会**把面板重置到第 1 页，会保留上次停留页 ⇒ 第一次采集静默漏掉第 1 页。
> 必须先连点左箭头直到顶部弹「已经是第一页了」（`--rewind` 已固化）。

**一个补充事实**: 统计面板 248 个对手 > 记录去重后 237 个 ⇒ 记录面板确实不是每一场都留下，
**但漏掉的全是我赢的场次，赢过我的一个都没漏**。

### 为什么"只多出 90 多人"（算术链，链条闭合）

```
360 条流水（不是 360 个人）
  → 237 个不同对手
    → 其中 123 人我从没输过
      → 114 人赢过我
        → 按口径（首次交锋即负）排掉 5 个"首战我赢、后输"
          → 109 人入名单
            → 其中 20 人库内已有
              → 净新增 89 人
```

### 一次自我纠错

中途一度误判"记录面板被截断"（依据: 「重生的帅军神」在记录里搜不到）。
实为**用错字搜索** —— 转录里写的是「**再生**的帅军神」（3 行全败），与统计面板"败 3"完全吻合。
教训: 名字核对必须走模糊匹配，不能拿手打 grep 的零结果下结论。

写入方式: `db.mark_no(full_name, reason="arena_stat:ever_lost(败N)")`（reason 存入 `events.detail` 可溯源）。
**区号必须带上** —— 统计面板不显示区号，而库内名单一律存 `NN区 名字` 全名；只写裸名会让模糊匹配因长度差异而漏命中。
